# Step 03 Delivery History

## 2026-11-05 - Accepted

Delivered `.apm/skills/sdp-core` (SKILL.md, `scripts/sdp.py`, run-record JSON
Schema) and 52 contract tests in `tests/contracts/test_validator.py`.

### Evidence

- Windows (Python 3.11): 52 tests, 2 skipped (symlink creation not permitted for
  this account). WSL (Python 3.12, Git 2.43): 52 tests, 0 skipped, which also
  exercises POSIX `fcntl` locking and symlink refusal.
- Mutation checks: eight deliberate rule removals (plan fingerprint, triggers,
  escalation ceiling, human check, package-folder exclusion, review skipping,
  stale evidence, revision check) were each caught by a test. Re-run after the
  hardening below with the same result.
- Schema parity: the `jsonschema` library (development only) and the validator
  both accept a real record and reject the same malformed variants.
- `apm pack --dry-run --verbose` lists the scripts and schema. It also exposed
  generated bytecode, which is now ignored and not written by the tests.

### Independent security and correctness review

Conditional pass. Triage:

- Fixed: candidate fingerprint, plan, and record are now all evaluated under the
  write lock (previously computed before it). Reads are size-capped and recursion
  errors are handled. `PLAN.md` and `DELIVERY-RUN.json` that are symbolic links
  are refused at resolve, read, and write time. Approval updates the plan and
  record in one locked operation.
- Fixed (found while triaging): a candidate that failed a stage could be re-passed
  without changing; it is now refused until the candidate changes.
- Widened the agent-identity heuristic; it avoids rejecting human surnames that
  merely end in "bot".
- Rejected: the reported symlink "write-through" on `PLAN.md`. Replacement uses
  `os.replace`, which swaps the directory entry rather than writing through a
  link; refusing symlinks covers the remaining read-side risk.
- Documented limits: identities are asserted strings and a caller can assert any
  human name; stage-name actors cannot be distinguished from humans so named;
  anyone with write access can edit files directly. See `docs/PROTOCOL.md`.

The fixes were verified by regression tests and mutation checks; a second
independent review of the delta was not run.

### Deviations and Limits

The suite takes minutes on Windows because each test spawns Git several times;
it takes seconds on Linux. Python and Git are prerequisites of the validator and
are documented. The validator is not wired into any agent yet. Nothing here
proves enforcement by a host or agent; that is Steps 05 and 06.

The user's continue instruction is recorded as approval and acceptance.
